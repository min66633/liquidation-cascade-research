# 연구 로그

## 2026-07-31 — 착수, 문헌조사 + 데이터 경로 확정 + 수집기 가동

### 문헌조사 결론
세 갈래 문헌이 존재하나 두 가설의 증거 강도가 다르다.

- **이론**: Brunnermeier-Pedersen (2005 예측매매, 2009 마진 스파이럴), Osler (2005 FX 스탑 캐스케이드)
- **강제청산 → 되돌림 실증 (강함)**: Bian et al. (2018) 2015 중국 폭락 계좌 단위 — 마진콜 임박
  투자자 보유 종목의 비정상 하락이 **이후 40영업일에 걸쳐 반전**. Coval-Stafford (2007) fire sale.
- **크립토 조기경보 (부정적)**: arXiv 2607.27070 — BTC 캐스케이드 7건(2022–2025)에 39개 설정 스윕,
  critical slowing down 신호가 **이벤트마다 달라 재현되지 않음**. 관세 뉴스 쇼크 2건에서는 침묵.
  → "청산 시점 사전 포착" 단독 알파(H1)는 이미 반증 쪽. 레짐 필터로만 사용.

**갭**: perp 청산 피드를 쓴 *거래가능 전략* 검증이 사실상 없음. 특히 청산 밀도 L(p)로
슈팅 크기를 사전 추정하는 접근은 선행연구 부재.

### 데이터 경로 실측 (직접 API 호출로 확인)
- `clearinghouseState`에 `liquidationPx` **직접 제공** — Coinglass 히트맵 같은 역산 추정치가 아닌 ground truth
- `batchClearinghouseStates`는 공개 API에서 **HTTP 500** (노드 RPC 전용) → 배치 불가, 순차만
- 유효 처리량 **600주소/분** (weight 1200/분 ÷ 2)
- 리더보드 **40,976주소 무료**, 상위 1,000계좌가 계좌가치의 **87.5%**
- Binance `forceOrder`는 초당 심볼별 1건만 → 캐스케이드가 격렬할수록 누락률 상승하는 **체계적 편향**.
  Bybit `allLiquidation`(2025-02-25~)이 전건 제공 → Y변수는 Bybit로 가야 함
- Binance `/futures/data/*`는 **최근 30일만 보관** → 즉시 적재 개시

### 설계 판단
1. **hl_positions 최우선** — L(p)는 백필 불가. 다른 모든 것은 뒤로 미뤄도 되지만 이건 안 됨.
2. **계좌가치 랭킹만으로는 부족** — 실측에서 상위 계좌 다수가 포지션 0. 청산 연료가 아님.
   → 관측 명목가 기반 재랭킹 + 꼬리 15% 회전 스캔(사각지대 제거)
3. **스윕 번짐 기록** — 1,000계좌 스윕에 ~125초. 계좌별 `ts` + 시작/종료 mid 저장으로 사후 보정 가능
4. Bybit allLiquidation은 3순위 (Tardis.dev로 2025-02-25 이후 유료 백필 가능하므로 유실 압박 없음)

### 가동 확인

### 코드리뷰 반영 (같은 날)
리뷰에서 실제 결함 12건 확인, 전부 수정 후 재검증. 치명적이었던 두 건:

1. **랭킹이 플랫 고래를 영구 추방** — `fillna`로는 관측값 `0.0`(NaN 아님)이 안 걸려
   순간 플랫인 계좌가 최하위로 확정 강등. 강등되면 폴링에서 빠지고, 빠지면 관측될 수 없어
   복귀 불가. 실측으로 $4.6B 계좌가 2위→37,273위 추락 확인. 관측 46계좌 중 35개(76%)가
   순간 플랫이었으므로 L(p)의 대부분이 사라질 뻔했다.
   → `rank_key = max(관측명목가, 계좌가치 × 0.25)`
2. **Binance 병합이 읽기 실패 시 히스토리 전체 파괴** — `read_parquet` 예외 후에도
   신선한 500행만으로 덮어쓰고, `before=0`이라 로그에는 `+500 new rows`로 정상처럼 찍힘.
   30일만 서빙되는 원본의 유일본이라 영구 손실.
   → 격리(`.corrupt.<ts>`) 후 새로 시작, 격리 실패 시 쓰기 포기

그 외: 스윕 벽시계 마감 부재(이론상 15시간 스윕), Pacer 완화 조건이 사실상 도달 불가라
8배 상한으로 단방향 래칫, 3개 parquet 쓰기 실패 격리 부재로 고아 파일 발생, sweeplog
스키마 드리프트(이미 디스크에서 발생 — 1회 복구 수행), 유니버스 갱신 실패 시 33MB 재다운로드
증폭(하루 9.5GB), `Retry-After: -1` → `ValueError`로 스윕 사망, 커서가 재정렬되는 리스트의
위치 인덱스라 커버리지 보장 붕괴, 중복 실행 시 read-modify-write 경합.

검증: 정상 스윕 / 마감 초과 스킵 / `--explore-frac nan` / 중복 실행 차단 / 6스윕 교차
디렉터리 읽기 / Binance 중복제거(505행, 1000행 아님) 전부 통과.

### 열린 이슈
- 스윕 주기 300초가 캐스케이드 관측에 충분한지 미검증. L(p)는 완만히 변하므로 사전 상태
  포착엔 무리 없어 보이나, 캐스케이드 *중* 소진 과정을 보려면 적응형 가속이 필요할 수 있음
- HL 청산맵(글로벌 OI 16%)이 시장 전체 캐스케이드를 대표하는지 — 이 연구의 핵심 검정 대상

- **체결은 완전 중첩이다.** |S_실측(u) − P(X≥u)| 최대 = 0.0000. 사다리는 Sharpe 를

  -> 사다리의 근거를 "분산"에서 "분포 형태 개선"으로 바꿔 써야 한다.
- **숏풋 가설은 반증.** X 가 커질수록 평균 손익이 *증가*한다(2.0→550.7bp). 대신 최심
  구간에서 평균 +550.7 / 중앙 −7.2 — 손실 구조가 아니라 복권 구조다.

**잠재 버그 수정 (downloaders/binance_depth.py)**

- `--days-file` 을 utf-8-sig 로 연다(BOM 이면 첫 날짜가 404).

### 4. 방법론 오류 정정 — 점추정을 확률모델이라 불렀다

사용자 지적: "X 를 예보하는 거 제 말대로 확률모델로 했나요?"

**아니었다.** predict_x.py 는 OLS 점추정이다. 확률모델은 P(X >= u | F) 라는 함수
전체이고, 배치의 기대값 EV(u) = P(X>=u|F) * E[r|X>=u,F] - c 에서 **두 항 모두 분포에서
나오는데 점추정에서는 어느 쪽도 나오지 않는다.** 예측값에 1.25를 곱한 것은 분위수가
아니며 아무 확률적 의미가 없다.

더 큰 문제를 하나 더 찾았다: **MATH.png 2절이 S(u) = P(X >= u) 를 무조건부로만
정의**하고 3절 EV 와 4절 무차별성이 전부 그 위에 서 있다. 설계가 요구하는 것은
조건부 P(X >= u | F_t) 다. **이것이 "확률모델은 이미 있다"는 오해의 근원이었다.**

=> **무차별성은 조건부 세계를 반증하지 않는다.** 무조건부 곡선이 평평해도 사건별
곡선이 서로 다르면 사건마다 다른 u 를 고를 수 있다. 조건부는 아직 미검정이다.

=> **PROB_MODEL.md 신설.** 확률모델의 정본. 형태:

    log V | F_t ~ N( mu(F_t), sigma(F_t)^2 )     <- mu 와 sigma 를 둘 다 모형화
    P(X >= u | F_t) = Phi( [mu - log D_t - (log u - a)/gamma] / sigma )

sigma 를 상수로 두면 그건 다시 점추정이다. **L(p) 가 들어갈 자리는 mu 하나로
특정됐다** — 구조식도 보정 검정도 배치 규칙도 바뀌지 않는다.

합격 기준은 R2 가 아니라 (1) 보정(Kupiec) (2) 판별(조건부 IQR 비 >= 1.5) 이다.
R2 는 mu 만 재는데 배치에 쓰이는 것은 분위수이고 그건 sigma 가 정한다.

### 6. 그리고 사용자 지적이 원인을 짚었다 — **D 는 확률변수다**

> "오더북 주문이 확정이 아니라 마켓메이커나 봇이 호가를 넣었다 뺐다 하기 때문에

    log X = a + gamma log V - gamma log D_t - gamma log W
                                             ^^^^^^^^^^^^ 빠져 있던 항
    sigma^2 = gamma^2 (sigma^2_logV + sigma^2_logW - 2Cov)

**이 한 가지가 관측된 실패 넷을 전부 설명한다:**

| 실패 | 설명 |
|---|---|
| sigma 모형 역방향(0.78) | 지배적 불확실성이 log W 인데 사전특징에 없다 |
| 보정이 한 방향으로 깨짐 | log W 항을 빼먹었으니 위치가 계통적으로 어긋난다 |
| u_act/u_pred = 9.2배 | **그 산포 [1.7, 13.8] 가 곧 W 의 분포다** |
| V/D_t = 0.65% | 분모가 허수다 |

gamma 만 두 방법에서 일치한 것도 일관된다 — W 는 곱셈 상수라 기울기를 안 건드린다.

**질문이 바뀐다**: V(강제매도량) 예보 -> L(p) 필요, 6개월 대기
                => **W(호가 잔존율) 예보 -> 30초 호가로 이미 관측 가능**

그리고 이쪽이 목표 설계의 "실시간으로 대조" 와 더 맞는다 — 정적 L(p) x D 대조가
아니라 **D 가 무너지는 속도**를 보는 것이다. **QW = 다음 문항. 미검정.**

>  밀릴지 계산. MM이나 기타 사람들이 호가를 빼거나 넣기도 하는데 이건 확정할 수 없으니
>  확률모델로. 그리고 아마 MM은 OI가 많이 쌓여있는 쪽을 터트리려고 할 확률이 높다고 보고,
>  청산이 일어났을 때 순식간에 가격이 얼마나 밀릴지 오더북 물량을 실시간으로 매번
>  계산해 확률을 계속 조정."

두 가지가 모델을 바꾼다.

**(1) 확률모델인 이유가 명시됐다.** W(호가 잔존율)를 확정할 수 없다는 것 —
그것이 이 설계가 결정론이 아니라 확률모델인 이유다. TARGET_DESIGN 1.1 절.

**(2) W 는 잡음이 아니라 L 과 얽혀 있다.** 지금까지 내 모델은 W 를 외생 잡음으로
놓았다. OI 두꺼운 쪽을 터뜨리려는 유인이 있다면 dW/dL < 0 이고, 두 항이 같은 방향으로
민다 — 물량이 더 쏟아지고 동시에 호가가 더 사라진다. **곱해진다.**

    log X = a + gamma ( log V(u) - log D_t - log W(u) ),  V(u)=∫L, dW/dL<0

이것이 V/D_t=0.65% 인데 9.2배 밀리는 이유의 유력한 후보이고, sigma 모형 실패의
설명이기도 하다 — W 가 L 에 조건부인데 사전 특징에 L 이 없었다.

문헌: Brunnermeier & Pedersen (2005) Predatory Trading / Osler (2005). 둘 다 참고문헌에 있었다.

비판적 단서: MM 은 스프레드로 벌지 방향으로 벌지 않으므로 '터뜨린다'는 의도는
방향성 트레이더에 더 맞고 MM 은 역선택 회피로 뺀다. 그런데 **관측 예측이 같아서**
어느 쪽이 맞는지 몰라도 검정은 성립한다.

**=> 6절의 "L(p) 가치가 흔들린다"가 뒤집힌다.** L(p) 는 V 만이 아니라 W 도 예보한다.

### 18. 사용자 지적 3 — 나누기가 순차 과정을 숨긴다

> "V를 왜 D로 나눠요? 가장 가까운 가격대부터 밀린다고 가정하면... 확률로 추정해야할건
>  mm 혹은 기타 참여자의 주문 추가 또는 취소를 추정해야하는거 아닐까요?"

맞다. 물리는 순차 흡수다:

    X = inf{ u : integral_0^u [ d_rest(v) + delta(v,t) ] dv >= V }

V/D 는 이 식의 **닫힌 해**이고 두 가정 위에 선다: (1) 호가 모양이 멱함수 -> **검증됨**
(적합 R2=0.99), (2) delta=0 -> **틀림**. gamma 가 두 방법에서 일치한 건 (1) 의 증거다.

**스칼라 W 는 조잡하다.** 실제 대상은 delta(v,t) — 가격대마다 다르고 시간에 따라
변하는 함수다. 틱 예측은 필요 없고 캐스케이드 창 전체의 **분포**면 된다.

### 19. 정정 — 9.2배를 W 로 귀속한 것은 과잉주장

liq_cluster 의 u_pred 계산에 쓴 V 는 **Bybit 청산만**이다. Bybit 는 perp 의 10~15%,
청산은 전체 테이커 물량의 ~10%. **실제로 호가를 먹은 양은 한두 자릿수 크다.**
9.2배는 호가철수와 V 과소측정이 섞인 값이고 나는 전부 W 탓으로 돌렸다.
같은 이유로 "V/D=0.65% 라 분모가 허수" 도 성립하지 않는다.

### 23. Hawkes — 모듈 불합격, 그러나 방향은 확인

### 38. R-4 (analysis/amplification.py) — 증폭 가설 기각

n 을 시각이 아니라 **OI 파괴량**에서 직접 쟀다. 분기과정 S = S0/(1-n) 이므로
A = S/S0, n = 1 - 1/A. **커널도 타임스탬프도 안 쓴다 = Hawkes 와 독립이다.**

**5분봉 / 21종 / 2020-09-03 ~ 2026-06-17 / 청산 이벤트 1,005건**

| | A | n |
|---|---|---|
| **OI 실측** | **1.443** (CI [1.382, 1.505]) | **0.307** |
| 타임스탬프 Hawkes 멱함수 | 5.03 | 0.801 (잔차 불합격) |
| 타임스탬프 Hawkes 지수 | 3.02 | 0.669 |

33.1% 가 1바에서 끝난다. **증폭이 작다.**

핵심 검정도 **반대 부호로** 실패했다. y/(sigma*sqrt(S0/ADV)) 를 A 에 회귀한
기울기가 **-1.413 (t=-2.3)**. A 오분위별 되돌림 38.0 / 84.6 / 91.5 / **4.6**.
-> **증폭이 클수록 되돌림이 작다.** 캐스케이드가 계속되면 계속 밀린다는 뜻이고
증폭 가설과 정반대다.

**+0.173($t$=+2.0)으로 뒤집힌다** — 지도 결합 패널에서도 +0.316($t$=+3.2)으로
재현. 표시 재고는 위기에 보호하지 않는다. 회복력은 −0.098($t$=−4.0)로 3배,
취소압은 +0.101($t$=+4.0)로 3.6배 강해진다. **설계 원문("호가는 확정 물량이
아니다")이 데이터로 돌아왔다 — $D_{\text{eff}}$ 는 재고형이 아니라 유량형이어야
한다.** 꼬리도 이전되지 않는다(평시 학습 p=0.75 분위의 캐스케이드 위반 0.362).

**지도(①)는 아직이다.** 전체 창 $t$=+7.4 이나 증분 $R^2$ +0.0002 — 기준(0.02)의
1/100. 조건부는 커버리지 7세그먼트로 판정 불가. §3.1 독트린대로 계속 기다린다.

**불편한 관찰 하나**: 같은 창에서 라이브 페이퍼는 **2건 발화·0건 체결**이었다.
캐스케이드 23건이 지나가는 동안이다. §6.18 이 고른 z/dOI 방아쇠가 옳은지,
기준선(2%/15분)을 페이퍼에 병행시켜 전방으로 정면 비교한다 (**D-17 신설**).
리플레이는 구조 유지 확인: 트리거 mid 진입 +15분 +15.1bp / +60분 −11.1bp —
"15분에 결판"(R-6) 재현. 60분 내 리바운드 +97.5bp($t$=7.5, 23건 중 22건).
